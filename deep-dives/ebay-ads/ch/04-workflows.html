Core Workflows & Processes

1. Tracking & Attribution (Sojourner System)

Accurate tracking is critical. User clicks an ad on mobile, switches tabs, clicks item on desktop — the system must link these events to one conversion.

Key Challenge: Multi-tab browsing, cross-device tracking, and missing data points in the user journey.

Tracking Tags

  • siid (Source Impression ID) — Unique ID of the initial ad impression
  • ciid (Current Impression ID) — Current page impression (for multi-tab tracking)
  • UBI Tables — User Behavior Interaction logs; raw click/view events
  • Converted to standard format in data pipeline

Attribution Pipeline

  • Kafka ingests raw click/view events with siid/ciid tags
  • Spark Hadoop job joins clicks to conversions within 7-day window
  • Attribution model (last-click, first-click, multi-touch) applied
  • ClickHouse materialized view joins with GMV for daily reporting

Data Quality Checks

  • Verify click volume matches from multiple sources
  • Monitor attribution ratio for sudden drops (sign of tracking failure)
  • Reconcile with seller-reported clicks
  • Anomaly detector flags 20%+ swings in attribution

2. Experimentation & A/B Testing (Touchstone)

Every change to ranking, pricing, or UI flows through experimentation before production rollout. Use the Workflow simulator at the top — scenarios Experiment ramp and Deploy pipeline use the same phase strip, packet-on-wire, and log pattern as the tech-stack simulators.

Tracking Methods

  • Legacy ET Tags — Placement-level; less granular
  • Modern XT Tags — Event-level; precise impact measurement
  • Real-Time Dashboards — Update every 1-5 minutes during ramp
  • Flink consumes tagged events; ClickHouse queries for metrics

Statistical Rigor

  • Sample Size Calculation — Determine N needed to detect effect
  • Sequential Testing — Early stopping if clear winner emerges
  • Multiple Comparisons Correction — Bonferroni adjustment if 100+ experiments
  • Power Analysis — Minimize false positives and false negatives

3. Code Deployment & Change Tracking

Code changes must be correlated with metric anomalies for quick RCA. The deploy scenario in the simulator above walks merge → image → staging → production with ServiceNow logging.

Sequential Deployment Order

  • Workers First — Background job consumers updated first
  • Beat Next — Scheduling rules applied next
  • API Last — Request handlers rolled out last
  • Prevents version mismatch between services

Rollback Strategy

  • Quick Rollback — Keep previous version in ServiceNow; redeploy if needed
  • Canary Deployment — Route 1% traffic to new version first
  • Smoke Tests — Quick sanity checks (API up, CPU normal)
  • Drain Period — Wait 30-60s before killing old pods

Version Management

  • Semantic Versioning — v1.2.3 for releases
  • Commit Hash — Full git hash in Docker image tag
  • Manifest Tracking — Link deployed version to JIRA tickets
  • Rollback Records — Who rolled back, when, and why

4. Data Quality & Reconciliation

Periodic jobs verify metrics match across systems (Kafka, ClickHouse, Hadoop, Elasticsearch).

Daily Reconciliation Jobs

  • Raw Event Count — Kafka ingestion vs. Hadoop received
  • Aggregation Accuracy — ClickHouse sum(gmv) vs. Hadoop sum(gmv)
  • Deduplication Check — Raw events vs. deduplicated events
  • Late Event Backfill — Delayed events matched to correct time bucket

Alerts on Mismatch

  • Threshold: > 2% discrepancy triggers investigation
  • Automated email to data quality team
  • Dashboard shows which data pipeline is lagging
  • Potential causes: batch job failure, schema change, clock skew
