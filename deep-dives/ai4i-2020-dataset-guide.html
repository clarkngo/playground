AI4I 2020 — Predictive Maintenance

A synthetic milling machine dataset designed for classification and explainable AI research. 10,000 observations · 14 features · 5 labeled failure modes · 3.4% positive rate. Published by S. Matzka at the Third International Conference on Artificial Intelligence for Industries (2020).

Feature Dictionary — All 14 Columns
# Feature Name Type Range / Values Description & Notes
1 UID integer 1 – 10,000 Unique row identifier. Drop before modeling — no predictive signal, causes data leakage if included.
2 Product ID string L12345, M12345, H12345 Letter prefix (L/M/H) + serial number. The letter is useful as a categorical; the serial number carries no signal. Extract the type prefix into its own feature.
3 Type categorical L (50%), M (30%), H (20%) Product quality variant. L = low, M = medium, H = high. Affects OSF threshold and tool wear increment per minute (H+5, M+3, L+2 min). Must one-hot or ordinal encode. Critical for OSF prediction.
4 Air Temperature [K] float ~295 – 304 K Random walk, sigma=2K, normalized to 300K. Represents ambient shop-floor temperature. Used in HDF trigger via temperature delta. Raw value less useful than delta with process temp.
5 Process Temperature [K] float ~305 – 314 K Random walk, sigma=1K, equals air temp + 10K. Cutting zone temperature. HDF fires when (Process Temp − Air Temp) < 8.6K AND RPM < 1,380. Engineer the delta feature explicitly.
6 Rotational Speed [rpm] float ~1,168 – 2,886 rpm Calculated from 2860W power with normal noise. Used in PWF (power calc), HDF (low RPM trigger), and as input to derived Power feature. High variance — check for outliers.
7 Torque [Nm] float ~3.8 – 76.6 Nm Normal distribution, mu=40Nm, sigma=10Nm. Never negative in dataset. Used in PWF (power calc), OSF (wear × torque interaction). Most important single raw feature for failure prediction.
8 Tool Wear [min] float 0 – 253 min Accumulated wear time. H-type adds 5 min/part, M-type 3 min/part, L-type 2 min/part per cycle. Used directly in TWF trigger (200–240 window) and OSF interaction (wear × torque). Second most important feature.
9 Machine Failure binary 0 / 1 Primary target variable. 1 if any of the 5 failure modes fired. 339 positive cases out of 10,000 (3.39%). Class imbalance requires SMOTE, class weights, or threshold tuning. Do not use as a feature — it IS the label.
10 TWF binary 0 / 1 (120 cases) Tool Wear Failure label. Used for multi-class / multi-label failure mode classification. Leaks into Machine Failure — exclude all 5 failure mode columns when predicting Machine Failure.
11 HDF binary 0 / 1 (115 cases) Heat Dissipation Failure label. Triggered by low temp delta + low RPM. Multi-label target for failure mode classification experiments.
12 PWF binary 0 / 1 (95 cases) Power Failure label. Triggered by power outside 3,500–9,000W. Best predicted by the engineered Power feature — raw torque + RPM alone are weaker predictors.
13 OSF binary 0 / 1 (98 cases) Overstrain Failure label. Best predicted by the OSF factor (Tool Wear × Torque). Thresholds differ by Type — an interaction term between OSF factor and Type encoding is powerful here.
14 RNF binary 0 / 1 (5 cases) Random Failure label. 0.1% base probability regardless of sensor state. Only 5 cases — essentially unpredictable from features. High model recall on RNF signals overfitting or data leakage, not genuine prediction.

Feature Engineering — Derived Features
Feature Formula Failure Mode Why It Matters
Machine Power [W] Torque × (2π × RPM / 60) PWF The single most important derived feature. PWF is triggered exclusively by power leaving the 3,500–9,000W band. Without engineering this, PWF classification relies on correlated proxies (torque, RPM individually) that are weaker predictors.
Temp Delta [K] Process Temp − Air Temp HDF HDF fires when this delta drops below 8.6K. The delta removes baseline drift from both signals. Raw temperature values alone contain almost no HDF signal because both channels move together. The delta is the HDF signal.
OSF Factor Tool Wear × Torque OSF Captures the interaction between wear state and current mechanical load. Without this, a linear model misses OSF because the effect requires both features simultaneously exceeding thresholds. Pair with Type-conditioned threshold as a feature or use in tree-based models that capture interactions natively.
Type (extracted) Product ID[0] or Type column OSF, TWF Type is already in the dataset but must be encoded (one-hot or ordinal). H/M/L variants carry different tool wear increment rates and OSF thresholds. Models that drop Type lose important conditional behavior — OSF thresholds differ 18% across type variants.
Tool Wear Rate ΔTool Wear / Δtime TWF Requires time-ordered data. Detects abnormal wear acceleration that precedes TWF before the absolute 200-min threshold is reached. Useful for RUL estimation. Not computable in the static Kaggle CSV without row ordering context.
# Python: Engineer the 3 key derived features import numpy as np import pandas as pd df = pd.read_csv("ai4i2020.csv") # 1. Machine Power [W] — critical for PWF df["Power_W"] = df["Torque [Nm]"] * (2 * np.pi * df["Rotational speed [rpm]"] / 60) # 2. Temperature Delta [K] — critical for HDF df["Temp_Delta_K"] = df["Process temperature [K]"] - df["Air temperature [K]"] # 3. OSF Interaction Factor — critical for OSF df["OSF_Factor"] = df["Tool wear [min]"] * df["Torque [Nm]"] # 4. Type extracted from Product ID (redundant with Type col, but explicit) df["Type_Code"] = df["Type"].map({"L": 0, "M": 1, "H": 2}) # 5. Drop leakage columns before modeling LEAKAGE_COLS = ["UDI", "Product ID", "TWF", "HDF", "PWF", "OSF", "RNF"] X = df.drop(columns=LEAKAGE_COLS + ["Machine failure"]) y = df["Machine failure"]
ML Modeling Considerations
  • ⚖️ Address class imbalance first. 96.6% negative rate means accuracy is a misleading metric. Use class_weight="balanced" in sklearn classifiers, SMOTE oversampling via imbalanced-learn, or threshold tuning on predicted probabilities. Always evaluate with F1, PR-AUC, or Matthews Correlation Coefficient — not accuracy.
  • 🚰 Prevent data leakage. The 5 failure mode columns (TWF, HDF, PWF, OSF, RNF) are components of the Machine Failure label. Including them as features causes near-perfect but meaningless classification. Also drop UID and Product ID serial number — they are identifiers with no predictive signal.
  • 🔧 Engineer Power, Temp Delta, and OSF Factor before fitting. These three derived features are explicitly referenced in the failure mode trigger conditions. Tree-based models (Random Forest, XGBoost) can approximate them with enough depth, but explicit features improve both performance and interpretability.
  • 🌲 Tree-based models outperform linear models here. The failure triggers are threshold-based AND conditions — exactly what decision trees and gradient boosting are built for. XGBoost or Random Forest with class weights is a strong baseline. Logistic regression will underperform unless you add polynomial/interaction terms manually.
  • 🔍 Use SHAP for explainability. The original AI4I paper focuses on XAI. After fitting, compute SHAP values to show which features drove each prediction. This is a core deliverable of the paper — and a strong signal that your model has learned the right mechanisms, not spurious correlations.
  • 🎯 Multi-label vs binary classification. You can train a single binary classifier for Machine Failure, OR train 4 separate binary classifiers (one per predictable failure mode: TWF, HDF, PWF, OSF). Multi-label classification per mode enables failure-specific XAI — useful for the maintenance use case where knowing the failure type drives the response.
  • 🎲 Ignore RNF as a classification target. 5 cases are insufficient for reliable model evaluation. RNF is intentionally unpredictable from sensor data. Focus modeling effort on TWF, HDF, PWF, and OSF. RNF cases do count toward the Machine Failure label and should not be excluded from the primary binary task.
  • 📊 Calibrate probability thresholds. Default 0.5 classification threshold is inappropriate for imbalanced data. Use precision-recall curves on the validation set to find the threshold that achieves your target false-alarm rate (e.g., <10% FAR) while maximizing recall. Document the chosen threshold and its operational tradeoffs.

Domain Knowledge — Why the Data Looks the Way It Does
1 · CNC Milling Machine Fundamentals

A CNC milling machine removes material by pressing a rotating cutting tool against a workpiece. The spindle spins the tool; axis motors move the tool or table along a programmed path (G-code). Every sensor in AI4I maps to a physical phenomenon in this system.

SensorPhysical meaningWhy it matters for PdM
Air Temp [K]Ambient shop-floor temperature — rises slowly with shift time, HVAC load, nearby machines. Baseline for the thermal system.Not a failure predictor alone; its value is as the reference for the temperature delta used in HDF.
Process Temp [K]Temperature at or near the cutting zone — captured on spindle housing or coolant return. Always higher than air temp because friction and chip deformation generate heat. Nominally air + 10K.Tracks cutting zone heat. Divergence from the expected delta signals cooling degradation (HDF).
Rotational Speed [rpm]Spindle speed — how fast the cutting tool rotates. Determines surface cutting speed. Too slow → rubbing instead of cutting → heat buildup. Too fast for the material → tool shatters.Used in PWF (via power calc) and HDF (low-RPM cooling collapse). Not a standalone failure signal.
Torque [Nm]Resistance the workpiece exerts on the tool. Increases with depth of cut, feed rate, material hardness, and — critically — tool wear. A sharp tool slices; a dull tool plows.Most important raw feature. Rises with wear (TWF proxy), multiplied with wear for OSF, combined with RPM for power (PWF).
Tool Wear [min]Accumulated cutting time for the current insert. Not directly measured — computed from machine cycle logs. Wear is progressive: break-in → steady-state → accelerated failure.Direct TWF trigger. Also OSF factor component. The dataset adds 5/3/2 min per cycle for H/M/L, simulating type-dependent wear rates.
2 · The 5 Failure Modes — Physical Depth
TWFTool Wear Failure

What physically happens: Carbide inserts wear in three stages — break-in (rapid initial), steady-state (gradual, predictable), accelerated (exponential, imminent fracture). At 200–240 min the insert is at end-of-life. Flank wear increases tool-workpiece contact area, raising both friction and heat.

What operators observe: Surface finish degrades, parts go out of dimensional spec, torque rises, audible chatter or squealing. Catastrophic failure: insert fractures mid-cut, fragment lodges in workpiece or damages spindle taper.

Why the trigger makes sense: Tool wear is monotonically increasing — it never decreases in operation. The 200–240 min window reflects real variability; the dataset randomly assigns the failure point within that window for each tool.

Cost of missing it: Scrapped workpiece (especially in aerospace/automotive), spindle damage ($20K–$80K repair), unplanned line stoppage. Tool replacement costs ~$5–$50 — the failure cost is 1,000× the prevention cost.

HDFHeat Dissipation Failure

What physically happens: The temperature differential between process and air collapses below 8.6K while RPM is below 1,380. This combination means the machine is running slowly and heat is not being removed — the cooling system is failing, not the cutting process.

Why the delta matters more than raw temp: Both sensors drift together with ambient conditions. The gap between them is what the coolant system maintains. When coolant flow degrades (clogged nozzle, failing pump, low fluid), the gap collapses toward ambient + friction-only heat.

Why the RPM threshold: Below ~1,380 rpm, centrifugal coolant distribution in many spindle designs becomes ineffective — coolant does not reach the cutting edge. This is a machine-specific physics constraint encoded into the trigger.

Cost of missing it: Spindle bearing seizure (precision bearings are intolerant of thermal expansion beyond design limits), workpiece thermal distortion, accelerated tool wear. Bearing replacement: $10K–$50K plus 2–5 days downtime.

PWFPower Failure

Under 3,500W: The machine is doing almost no useful work. Causes: tool broke and is no longer cutting, spindle stalled, drive fault, or tool-path error (air-cutting). Motor draws current but produces no output.

Over 9,000W: Machine is overloaded. Causes: aggressive feed rate, wrong tool for material, worn tool running at full programmed speed, or jammed chip causing sudden torque spike.

Why Power = Torque × ω is the right metric: High torque at low RPM can be normal (heavy cut, slow speed). High RPM at low torque is also normal (light finish pass). The product is what loads the motor drivetrain. Neither raw feature alone predicts PWF — the derived feature is essential.

Cost of missing it: Drive inverter failure, spindle motor burnout, broken tool fragments in workpiece. Sustained over-power events destroy bearings through heat cycling.

OSFOverstrain Failure

What physically happens: A worn tool at high torque simultaneously — the already-degraded cutting edge is being asked to do maximum work. Edge geometry has deteriorated, heat concentration is higher, and stress cycling accelerates fracture. Thresholds: H > 11,000, M > 12,000, L > 13,000 min·Nm.

Sharp tool at high torque: Fine — the edge handles it. Worn tool at low torque: fine — low mechanical stress. Worn tool + high torque: dangerous — the interaction is superlinear.

Why thresholds differ by type: H-type variants are harder materials or tighter tolerances — configured for aggressive cutting, so the tool/spindle reaches its stress limit sooner. L-type runs softer materials or shallower cuts — accumulates the overstrain interaction more slowly, hence the higher threshold before failure fires.

Cost of missing it: Sudden tool fracture under load — more violent than end-of-life wear. Fragment can become a projectile. Workpiece scrapped. Spindle damage likely.

RNFRandom Failure

0.1% independent probability per observation regardless of sensor state. Represents latent defects and truly stochastic events: hidden crack in a carbide insert from manufacturing, transient electrical spike, hydraulic surge, loose fastener. These are not unpredictable because we lack sensors — they are unpredictable because the failure mechanism is either a pre-existing hidden defect or a single-event external perturbation. No additional sensor data changes this. Only 5 cases in the dataset — intentional and realistic. If your model claims high RNF recall, it is pattern-matching noise. The correct model behavior is to assign ~0.1% probability to RNF for all observations.

3 · Why the Features Are Correlated
Torque ↑ as Tool Wear ↑ (physical law): A sharp cutting edge has a small contact area and acts as a wedge — it fractures material cleanly ahead of it. A worn tool has a rounded flank that plows through material rather than cutting, dramatically increasing the contact force required. This is why tool wear is the leading predictor of torque rise, and why the OSF interaction term (wear × torque) captures the compounding effect.
Temperature ↑ as Tool Wear ↑: ~80% of cutting energy converts to heat. A worn tool requires more energy (higher torque at same conditions), and its degraded geometry is less efficient at conducting heat away through chip formation. More energy input + less efficient heat removal = process temperature rise that accelerates ahead of the wear curve.
Power = Torque × ω — exact physics, not approximation: The spindle motor converts electrical power to rotational mechanical power. P = τ × ω where ω = 2πN/60. This is exact for steady-state operation. The AI4I dataset generates RPM from a 2,860W baseline with noise, which is why power stays near the middle of the 3,500–9,000W band under normal conditions. Computing this feature is mandatory for PWF classification.
High Torque + Low RPM → Overheating: At low RPM, less material is removed per unit time — the tool dwells on each surface element longer, concentrating heat. Chips (which carry most heat away) form more slowly. Coolant distribution is less effective at low spindle speeds. Three effects compound: more heat generated per chip, less heat carried away by chips, less effective coolant distribution. This is the physical basis for the HDF AND condition.
Air Temp and Process Temp move together — normally: Both are random walks. Air temp fluctuates with environment; process temp tracks air temp + 10K. The delta is controlled by the cutting process and coolant system. When the delta narrows, it means the coolant is failing to maintain the temperature differential — not that cutting conditions changed. This is why the delta is the HDF signal and raw temperatures are not.
4 · Product Type (L/M/H) — Operational Meaning

Type controls two things in the dataset: tool wear increment per cycle (H+5, M+3, L+2 min) and OSF failure threshold (H: 11,000, M: 12,000, L: 13,000 min·Nm). Both reflect real operational differences between machining product quality variants.

TypeMaterial / toleranceWhy higher wear rateWhy lower OSF threshold
H (High)Harder materials, tighter tolerances (e.g. hardened steel, tight-spec aerospace parts)Harder material abrades the cutting edge faster per cycle. Slower feed rates mean more time in cut per part.Machine is configured for aggressive cutting parameters. Tool and spindle system reach stress limit sooner under high torque + wear combinations.
M (Medium)Standard engineering materials (e.g. mild steel, aluminum alloy)Moderate abrasion. Standard cutting conditions.Moderate stress tolerance. Middle threshold.
L (Low)Softer materials, wider tolerances (e.g. soft aluminum, rough machining)Less abrasive material, faster feed rates, shallower cuts — less tool contact time per part.Softer cutting conditions mean the tool and spindle can sustain higher combined wear×torque values before structural failure.
Modeling implication: Type is a conditioning variable — the failure behavior of the machine is fundamentally different across types. A model that drops Type conflates three distinct operating regimes, blurring the OSF decision boundary by up to 18% across threshold values. Always include Type (one-hot or ordinal encoded) and consider including an explicit OSF interaction term conditioned on Type.
5 · Why the Dataset is Synthetic — Implications for Generalization

What real milling data looks like

Sensor readings at 1–100ms intervals — not one row per cycle. Timestamps enabling time-series analysis (trend slopes, wear rate). Noise from sensor drift, calibration decay, electrical interference. Multiple correlated failure modes with ambiguous boundaries. Missing data from planned shutdowns and sensor faults. Label noise from imprecise maintenance log entries written hours after the event.

Matzka's simplifications

Each row is one independent observation — no temporal ordering. Failure triggers are exact threshold rules — real failures have fuzzy onset. Feature distributions are clean (normal, random walk) with no drift or outliers. Labels are exact — in reality TWF vs. OSF can be ambiguous for the same event. No sensor noise beyond modeled distributions.

Generalization caveat: Models trained on AI4I will be optimistic — the clean threshold boundaries are much easier to learn than real degradation curves. The lack of temporal structure prevents sequence models (LSTM, transformer) that exploit trend information — the most powerful real PdM technique. Transfer to a real production machine requires re-labeling, recalibration, and domain adaptation. Best use: benchmarking classification methods, demonstrating XAI approaches, learning ML methodology — not as a deployment-ready training set.
6 · ML Intuition for Manufacturing PdM

Why class imbalance is expected and correct: A well-maintained machine should fail rarely. If the dataset showed 50% failures it would mean the machine is catastrophically unreliable or the labeling is wrong. The 3.4% failure rate is realistic for a maintained production CNC. Imbalance is not a data quality problem — it is the ground truth of the domain. Never resample the test set.

Recall vs. Precision — the asymmetric cost structure:

False Negative — missed failure

Machine fails unexpectedly: $5K–$500K in downtime, scrap, and repair. Potentially a safety event. Unrecoverable once it happens. In high-value machining (aerospace, medical), a single scrapped part can cost more than an entire month of unnecessary preventive inspections.

False Positive — unnecessary work order

Technician spends 30–60 min inspecting a healthy machine. $50–$200 labor cost. Recoverable — the machine keeps running. The cost ratio is often 100:1 to 1,000:1 in favor of maximizing recall over precision.

Alarm fatigue is the ceiling: If precision drops below ~10–15%, operators start ignoring all alerts and the system fails as a human process. The practical operating point is the highest recall achievable while keeping false alarm rate below the fatigue threshold (~10–20% FAR). This is why precision-recall curve threshold tuning matters more than optimizing F1.

Why tree-based models dominate here: The failure triggers are AND-condition thresholds — (temp_delta < 8.6) AND (rpm < 1380) for HDF, wear * torque > threshold for OSF. This is a decision tree split by definition. Logistic regression needs explicit polynomial interaction terms to approximate these boundaries. Random Forest and XGBoost find them automatically and handle class imbalance well with class_weight="balanced" or scale_pos_weight.
