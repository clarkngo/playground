🔬 Demo 2 — NIST Post-Quantum Standards (2024)

Click each algorithm card to explore NIST's 4 selected post-quantum standards.

ML-KEM (CRYSTALS-Kyber)
FIPS 203 · Key Encapsulation Mechanism
Replaces: RSA/ECDH for key exchange
Math basis: Module Learning With Errors (MLWE) — lattice problem
Security levels: ML-KEM-512 (L1), ML-KEM-768 (L3), ML-KEM-1024 (L5)
Key sizes: 800B (L1) → 1568B (L5) public key
Performance: Faster than RSA-2048 for key generation and encapsulation
Deployment: Use ML-KEM-768 + X25519 hybrid for TLS 1.3 (IETF draft)
Only KEM in NIST PQC
ML-DSA (CRYSTALS-Dilithium)
FIPS 204 · Digital Signature Algorithm
Replaces: ECDSA/RSA-PSS for digital signatures
Math basis: Module Learning With Errors — lattice problem
Security levels: ML-DSA-44 (L2), ML-DSA-65 (L3), ML-DSA-87 (L5)
Signature sizes: 2420B (L2) → 4595B (L5)
Performance: Fast signing and verification, deterministic
Deployment: Primary recommendation for code signing, TLS certificates
Primary PQC signature standard
SLH-DSA (SPHINCS+)
FIPS 205 · Hash-based Signature
Replaces: ECDSA/RSA for signatures (hash-based alternative)
Math basis: Hash functions only — no lattice or number theory assumptions
Security levels: Multiple parameter sets (128s, 128f, 192s, 256f, etc.)
Signature sizes: 8KB (small) → 50KB (fast variant)
Performance: Slower than ML-DSA but based only on hash security
Why use it: Most conservative — security relies only on SHA-2/SHA-3 hardness
Most conservative security assumptions
FN-DSA (FALCON)
FIPS 206 · NTRU Lattice Signature
Replaces: ECDSA for constrained environments
Math basis: NTRU lattices (different from Module-LWE)
Security levels: FALCON-512 (L1), FALCON-1024 (L5)
Signature sizes: 666B (L1), 1280B (L5) — compact!
Performance: Very fast verification; complex signing (requires Gaussian sampler)
Caution: Implementation is tricky — requires careful floating-point handling
Compact signatures, complex impl.
🔀 Hybrid Mode: During transition, use classical + PQC simultaneously. Example: X25519 + ML-KEM-768 for key exchange. This provides security against both classical and quantum adversaries — even if ML-KEM is broken classically (unlikely), X25519 still protects you.

Which NIST-standardized post-quantum algorithm is specifically a Key Encapsulation Mechanism (KEM) — replacing RSA/ECDH for key exchange?

📚 NIST PQC Algorithm Roles
  • ML-KEM (FIPS 203): The ONLY KEM — replaces RSA/ECDH. Used to establish shared secrets for symmetric encryption. Not for signatures.
  • ML-DSA (FIPS 204): Digital Signature — replaces ECDSA. Used for code signing, TLS certificates, authentication.
  • SLH-DSA (FIPS 205): Hash-based Digital Signature — most conservative, based only on hash security.
  • FN-DSA (FIPS 206): NTRU lattice Digital Signature — compact signatures, complex implementation.

In hybrid TLS 1.3: ML-KEM-768 handles key exchange, ML-DSA-65 (or classical ECDSA) handles certificate authentication.
