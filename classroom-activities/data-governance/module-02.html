📚 Data Governance — Module 02

Data Quality & Metadata Management

🏦 Case Study: “GlobalTrust Bank: The Duplicate Records Crisis”

A multinational bank is experiencing operational inefficiencies due to poor data quality — duplicate records, missing contacts, invalid balances, and inconsistent formats. Students act as Data Governance Analysts to profile, clean, and catalog data using Databricks and OpenMetadata.

Case Overview
About GlobalTrust Bank

GlobalTrust Bank is a multinational bank storing customer records across multiple systems. Poor data management has led to compounding quality issues that now threaten regulatory compliance, risk analysis, and customer service.

IssueDescriptionBusiness Impact
Duplicate Customer IDsSame customer registered more than once across systemsIncorrect risk scoring & duplicate communications
Missing Contact InformationEmail and phone fields frequently nullFailed outreach, compliance gaps
Invalid Account BalancesNegative balance values present in operational dataFaulty financial reporting
Inconsistent Data FormatsDates, emails, and IDs vary by source systemIntegration failures, audit failures
⚠ Business Impact
Regulatory compliance risk
Inaccurate risk analysis
Degraded customer service
Failed audit trails
Problem 1
Duplicate Records
Customer ID 1002 appears twice with identical data — both records active in the system, inflating counts and distorting analysis.
Problem 2
Missing Contact Data
Customer 1003 has no email on file. Customer 1005 has no phone. Mandatory fields are treated as optional across ingestion pipelines.
Problem 3
Invalid Account Balance
Customer 1004 has a balance of −250. Negative balances pass ingestion without validation, corrupting downstream financial models.
Problem 4
Invalid Email Format
Customer 1004 email susan.clark@email is missing the TLD. No format validation exists at ingestion.

Lab 3 Data Quality Checks 4 checks +
▶ Lab Steps
Check 1 — Null Values
from pyspark.sql.functions import col, sum, when null_counts = df.select([ sum(when(col(c).isNull(), 1).otherwise(0)).alias(c) for c in df.columns ]) display(null_counts)
Check 2 — Duplicate Customer IDs
from pyspark.sql.functions import count duplicates = ( df.groupBy("customer_id") .count() .filter("count > 1") ) display(duplicates)
Check 3 — Invalid Account Balances
invalid_balances = df.filter(col("account_balance") < 0) display(invalid_balances)
Check 4 — Invalid Email Formats
invalid_emails = df.filter(~col("email").contains("@")) display(invalid_emails)

Lab 4 Data Cleansing Steps 8–11 +
▶ Lab Steps
Step 8 — Remove Duplicate Records
df_no_duplicates = df.dropDuplicates(["customer_id"])
Step 9 — Handle Missing Values
df_clean = df_no_duplicates.fillna({ "email": "unknown@email.com", "phone": "N/A" })
Step 10 — Correct Invalid Balances
df_clean = df_clean.filter(col("account_balance") >= 0)
Step 11 — Save Cleaned Table
df_clean.write.mode("overwrite").saveAsTable("bank_customers_clean") display(df_clean)
Post-cleanse result: 5 rows remain (duplicate 1002 removed, invalid balance 1004 removed). Nulls replaced with defaults for email and phone.
Optional Data Validation Using Great Expectations Steps 12–14 +
▶ Lab Steps
Step 12 — Install Great Expectations
%pip install great-expectations
Step 13 — Initialize Context
import great_expectations as gx context = gx.get_context()
Step 14 — Define and Run Expectations
validator = context.sources.pandas_default.read_csv(file_path) validator.expect_column_values_to_not_be_null("customer_id") validator.expect_column_values_to_be_unique("customer_id") validator.expect_column_values_to_be_between( "account_balance", min_value=0 ) validator.save_expectation_suite() validator.validate()
Great Expectations will flag duplicate customer_id and the negative balance row. Review the validation report output to confirm all three rules execute.

Learning Outcomes

After completing this module, students will be able to:

  • Apply data governance principles to improve data quality in a real banking scenario.
  • Implement validation frameworks using Databricks PySpark and Great Expectations.
  • Document and enforce enterprise data quality standards and governance policies.
  • Catalog datasets and manage metadata using OpenMetadata.
  • Track data lineage from source CSV to curated consumption table.
  • Establish data retention and deletion policies aligned with regulatory requirements.
  • Align technical practices with governance policies and business objectives.
