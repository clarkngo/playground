Chapter 2

👥 Roles & Responsibilities

Governance fails when everyone assumes someone else owns the data. This chapter defines the four core roles — CDO, Data Owner, Data Steward, and Data Custodian — and explains how a governance council ties them together into a decision-making structure.
Core Roles
🏢

Chief Data Officer

Executive sponsor. Sets the data strategy, secures budget, and holds the org accountable for data trustworthiness.

🗂️

Data Owner

Business-side. Accountable for a data domain (e.g., Customer, Product). Approves access and defines quality standards.

🔧

Data Steward

Day-to-day manager. Writes definitions, monitors quality, resolves data issues, and keeps the catalog up to date.

⚙️

Data Custodian

Technical implementation. Manages storage, pipelines, access controls, and backup — without setting policy.

"The Data Owner decides what the data means and who can access it. The Data Steward makes sure that decision is enforced day to day. The Custodian makes sure the infrastructure supports it." — Chapter 2, Data Governance: The Definitive Guide

🏢
Chief Data Officer (CDO)
Sets the vision, secures the budget, and is ultimately accountable for the organization treating data as a strategic asset.
C-Suite
Responsibilities
  • Define enterprise data strategy
  • Sponsor governance program
  • Chair the governance council
  • Report data KPIs to the board
  • Align data investment priorities
Decisions Owned
  • Data governance framework choice
  • Federated vs. centralized model
  • Budget for data tooling
  • Data monetization strategy
  • Escalated policy disputes
Key Partnerships
  • CEO / board — strategy
  • CTO — architecture alignment
  • Legal / Compliance — risk
  • Business unit heads — adoption
  • Data Owners — accountability
Typical Tools
  • Executive data dashboards
  • Governance program trackers
  • Data catalog (oversight view)
  • Risk & compliance platforms
🗂️
Data Owner
A senior business leader accountable for a specific data domain (e.g., Customer, Product, Finance). The final word on what the data means and who can see it.
Business VP / Director
Responsibilities
  • Own a named data domain
  • Approve access requests
  • Set domain quality standards
  • Review steward escalations
  • Sign off on data definitions
Decisions Owned
  • Who can access domain data
  • Retention period for domain
  • Authoritative definition of fields
  • Data sharing with external parties
  • Quality threshold for SLAs
Key Partnerships
  • CDO — strategy alignment
  • Data Stewards — day-to-day ops
  • Other Owners — shared datasets
  • Legal — sensitive data policies
  • IT / Custodians — tech controls
Typical Tools
  • Access approval workflow
  • Business glossary (approver role)
  • Domain quality scorecards
  • Data catalog ownership panel
🔧
Data Steward
The operational backbone of governance. Writes and maintains definitions, monitors quality metrics, resolves data issues, and is the person practitioners contact with data questions.
Senior Analyst / Manager
Responsibilities
  • Maintain business glossary
  • Monitor quality dashboards daily
  • Triage and route data issues
  • Catalog new data assets
  • Train staff on data standards
Decisions Owned
  • Term definitions (draft)
  • Data issue classification
  • Escalation to Data Owner
  • Catalog tagging standards
  • Quality rule thresholds
Key Partnerships
  • Data Owner — approvals
  • Custodian — technical fixes
  • Analysts — clarify definitions
  • Compliance — regulatory tags
  • Product teams — new data assets
Typical Tools
  • Data catalog (editor role)
  • Quality monitoring dashboards
  • Issue tracking (Jira / ServiceNow)
  • Business glossary editor
⚙️
Data Custodian
The technical implementer. Builds and operates the infrastructure that stores, moves, and protects data according to policies set by Owners and Stewards. Does not set policy.
Data / Platform Engineer
Responsibilities
  • Build and maintain data pipelines
  • Implement access controls
  • Manage storage & backups
  • Apply encryption & masking
  • Monitor infrastructure health
Decisions Owned
  • Technology stack choices
  • Storage tier / cost optimization
  • Backup frequency & RTO/RPO
  • Infrastructure SLA commitments
  • Security patching schedule
Key Partnerships
  • Stewards — quality rule impl.
  • Owner — access policy execution
  • Security team — controls review
  • DevOps — CI/CD for pipelines
  • Compliance — audit log delivery
Typical Tools
  • dbt, Airflow, Spark pipelines
  • Cloud IAM (AWS / GCP / Azure)
  • Data warehouse (BigQuery, Snowflake)
  • Monitoring: Datadog, OpenTelemetry
🏛️
Data Governance Council
The cross-functional committee that resolves conflicts, sets policy, and reviews governance health. Typically meets monthly. Chaired by the CDO.
Cross-Functional
Membership
  • CDO (chair)
  • All Data Owners (1 per domain)
  • Lead Data Steward
  • Head of IT / Platform
  • Legal / Privacy Officer
Agenda Items
  • Policy changes & approvals
  • Cross-domain disputes
  • Quarterly quality KPI review
  • New data initiative review
  • Compliance risk updates
Decision Authority
  • Approve new governance policies
  • Resolve owner-vs-owner conflicts
  • Authorize major data sharing
  • Set governance program roadmap
  • Escalation of last resort
Operating Model
  • Monthly standing meeting
  • Async approval workflows
  • Published meeting minutes
  • Rotating domain spotlight
