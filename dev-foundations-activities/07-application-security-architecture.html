Module 7 — Security

Application Security Architecture

Why This Matters
Problem

Applications that expose business logic directly to the internet without defense layers are vulnerable to SQLi, XSS, credential stuffing, and data breaches. Defense in depth requires layered controls.

Solution

Each security layer independently filters threats. Even if one layer fails, the next provides a backstop. WAF catches known attack patterns; auth prevents unauthorized access; input validation stops injections; encryption protects data at rest.

Real-World Use

OWASP Top 10 vulnerabilities map directly to these defense layers. AWS WAF, Cloudflare, and Azure Front Door implement the WAF layer. OAuth2/OIDC handles auth. Column-level encryption handles data protection.

Your Goal

Understand why security is a layered architecture, not a single control. Know where each layer sits in the request path and what attack it mitigates.

🛡️ WAF
Filters HTTP traffic for known attack signatures (SQLi, XSS, CSRF) before it reaches the application. Operates at the network/HTTP layer.
The outermost internet-facing defense always comes first.
🔀 API Gateway
The controlled entry point. Handles TLS termination, rate limiting, routing. Sits behind the WAF.
The gateway is the door; the WAF is the security guard at the perimeter.
🔒 Auth Service
Validates OAuth2 tokens or JWT claims. Determines who is calling before business logic runs.
You must know who is making the request before processing it.
✅ Input Validation
Sanitizes request parameters after auth. Prevents injections even from authenticated users.
Authenticated users can still send malicious input.
⚙️ Business Logic
Application code that processes the request. Only runs after all security checks pass.
Business logic is the last application-level step before persistence.
🗄️ Encrypted Store
Data stored with encryption at rest (AES-256). Only the business logic layer writes here.
Data is the most valuable asset — protect it at the storage boundary.
📋 Audit Log
Immutable record of security-relevant events. Required for compliance (SOC2, HIPAA, PCI-DSS).
The audit log records the outcome of every request, successful or not.

Unguarded Architecture (vulnerable)
You are designing the security architecture for a production web application. Sequence the defense layers from the outermost internet-facing control all the way to the data store and audit trail. Think about: What is the first line of defense against malicious HTTP traffic? Where does authentication happen relative to input validation? Why must data be encrypted at rest? Watch out for decoys that represent security anti-patterns.
⚠ Not all items belong in a defense-in-depth architecture — some represent dangerous anti-patterns that create vulnerabilities.
