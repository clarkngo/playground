Module 3 — REST APIs

REST API Gateway Architecture

Why This Matters
The Problem

Without a structured API layer, clients talk directly to backend services and databases. This exposes internal infrastructure, creates security holes, and makes it impossible to scale or change services independently.

The Solution

An API Gateway sits between clients and backend services, routing traffic, enforcing authentication, and abstracting infrastructure. Each request flows through a defined sequence of network and security layers.

Real-World Use

AWS API Gateway, Kong, and NGINX are used by companies like Netflix and Stripe to handle millions of API requests daily, enforcing rate limits, auth, and routing without touching application code.

Your Goal

Understand the full path of an API request from the client browser to the database, so you can reason about where latency, failures, and security vulnerabilities occur in production systems.

The Objective: You are designing the architecture of a REST API gateway system. Sequence the components from the client making a request, through the network and security layers, to the database at the back end.

Think about: How does a client find the server's IP address? What balances traffic across multiple servers? Where does authentication happen relative to the application? Watch out for decoys — some components do not belong in the critical request path.
📄 Component Reference

▼
👤Client
The browser, mobile app, or service that initiates an HTTP request. The client knows the domain name but not the server's IP address or internal architecture.
💡 Every request originates here before going anywhere.
🌐DNS Resolver
Translates a human-readable domain name (api.example.com) into an IP address. Every network request starts with a DNS lookup before a TCP connection can be made.
💡 The client needs an IP address before it can connect. What provides that?
⚖Load Balancer
Distributes incoming requests across multiple server instances to prevent any single server from being overloaded. Sits at the network edge, before application logic.
💡 Traffic is distributed before reaching application-level components.
🔐API Gateway
The single entry point for all API traffic. It handles routing, rate limiting, request transformation, and forwards requests to the appropriate backend service.
💡 The gateway sits between the load balancer and the auth + business logic layers.
🔒Auth Service
Validates the caller's identity by verifying JWT tokens, API keys, or OAuth credentials. Authentication must happen before the application processes the request.
💡 You must verify who is calling before letting them interact with business logic.
💻Application Server
Runs the business logic, validates inputs, processes the request, and coordinates reads/writes. It talks to the database but is never directly exposed to the internet.
💡 Business logic runs after auth, not before.
🗃Database
The persistent data store (PostgreSQL, MySQL, MongoDB) that the application server reads from and writes to. Databases are never directly reachable from the internet.
💡 The database is always the last component in the chain, not the first.
