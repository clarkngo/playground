Dev Foundations Activities — Answer Key
Correct sequences and distractor list for all 10 activities. For instructor use only.
⚠ Instructor reference only — do not share with students before they complete the activity.
Module 1 Container Runtime Architecture Live
1
Application Code
Developer writes source code first. Everything else builds on top of this.
2
Dockerfile (Image Definition)
Defines base image, dependencies, file copies, and entry point.
3
Container Image (Built Artifact)
Running the build produces a portable, self-contained image.
4
Container Runtime (Docker Engine)
Software layer (Docker Engine / containerd) that runs and manages containers.
5
OS Namespaces and cgroups (Isolation)
Linux namespaces isolate processes/networks; cgroups limit CPU and memory per container.
6
Host OS Kernel
All containers share the host kernel. The runtime talks directly to the kernel.
7
Physical / Cloud Hardware
CPUs, RAM, and storage managed by the OS kernel at the base of the stack.
Distractors (wrong answers)
Full VM Hypervisor Layer Guest Operating System Container Registry Cache Reverse Proxy / Load Balancer
Module 2 Distributed Version Control System Live
1
Local Working Tree
Files on disk that the developer edits directly.
2
Local Index (Staging Area)
git add stages changes here before committing.
3
Local Repository
git commit records a snapshot into the local .git object store.
4
Remote Repository
git push sends commits to the shared remote (GitLab / GitHub).
5
Branch Reference
A named pointer to a commit; branches isolate work streams.
6
Merge / Rebase Engine
Integrates branch history back into the target branch.
7
CI Trigger
Merge to main fires the CI pipeline automatically.
Distractors (wrong answers)
Central Lock Server Single Shared Branch FTP File Upload
Module 3 REST API Gateway Architecture Live
1
Client
Browser or app that initiates the HTTP request.
2
DNS Resolver
Resolves the hostname to an IP address before the connection is made.
3
Load Balancer
Distributes incoming requests across API Gateway instances.
4
API Gateway
Single entry point: handles routing, rate limiting, and request transformation.
5
Auth Service
Validates token / session before the request reaches business logic.
6
Application Server
Executes business logic and prepares the response.
7
Database
Persistent data store queried by the application server.
Distractors (wrong answers)
Client Writes Directly to DB Skip Auth Service Auth After Application Server
Module 4 Relational Database Internals Live
1
SQL Query Parser
Tokenizes and validates the SQL statement for syntax correctness.
2
Query Optimizer
Generates and selects the lowest-cost execution plan using statistics.
3
Execution Engine
Runs the chosen plan: scans, joins, filters, and aggregates data.
4
Buffer Pool
In-memory cache of disk pages; hot data stays here to avoid disk I/O.
5
Storage Engine
Manages on-disk data layout (InnoDB / B-tree pages).
6
Transaction Log (WAL)
Write-Ahead Log records changes before they hit the data file, ensuring durability.
7
Disk Storage
Physical or cloud block storage where data and log files persist.
Distractors (wrong answers)
Full Table Scan Optimizer Memory-Only Storage Skip Transaction Log
Module 5 Automated Testing Pipeline Architecture Live
1
Unit Test Runner
Executes isolated unit tests against individual functions and classes.
2
Code Coverage Analyzer
Measures which lines and branches are exercised by the tests.
3
Integration Test Suite
Tests component interactions: APIs, databases, and third-party services.
4
Test Report Aggregator
Collects results from all test suites into a unified report.
5
Quality Gate
Enforces pass thresholds (coverage %, zero failing tests) before continuing.
6
Artifact Store
Saves the verified build artifact (JAR, Docker image, etc.) for later deployment.
7
Deploy Gate
Final approval step that allows the artifact to proceed to deployment.
Distractors (wrong answers)
Deploy Before Tests Skip Coverage Check Manual QA Only
Module 6 Layered Software Architecture Live
1
Presentation Layer
UI or API surface that accepts user input and renders output.
2
Application / Use Case Layer
Orchestrates use cases; coordinates domain objects but holds no business rules itself.
3
Domain / Business Logic Layer
Core rules and entities; must not depend on any outer layer (SOLID Dependency Inversion).
4
Repository Interface
Abstraction boundary between domain and data access; defined by the domain layer.
5
Data Access Layer
Implements the repository interface; handles queries, ORM mappings.
6
Database
Persistent store; only the data access layer talks to it directly.
7
External Services
Third-party APIs, message queues, and email providers accessed via adapters.
Distractors (wrong answers)
Business Logic in UI Layer Direct DB Calls from Presentation Circular Dependency Layer
Module 7 Application Security Architecture Live
1
WAF (Web Application Firewall)
First line of defense; blocks SQLi, XSS, and known attack signatures at the edge.
2
API Gateway
Centralizes TLS termination, rate limiting, and routing before traffic reaches services.
3
Auth Service (OAuth2 / JWT)
Validates identity and issues/verifies tokens before business logic is reached.
4
Input Validation Layer
Sanitizes and validates request data at the application boundary.
5
Business Logic
Core processing; only reached after auth and validation pass.
6
Encrypted Data Store
Data at rest encrypted; secrets stored in a vault, never in code.
7
Audit Log
Immutable record of all actions for compliance, incident response, and forensics.
Distractors (wrong answers)
Store Passwords in Plain Text Skip WAF Auth After Business Logic
Module 8 CI/CD Pipeline Architecture Live
1
Source Repository
Developer pushes code; the push event triggers the pipeline.
2
CI Build Server
Checks out code, installs dependencies, and compiles the application.
3
Artifact Registry
Stores the versioned build artifact (container image, JAR) for traceability.
4
Staging Environment
Production-like environment where the artifact is deployed for testing.
5
Automated Test Suite
Integration, smoke, and end-to-end tests run against the staging deployment.
6
Approval Gate
Manual or automated gate that must pass before production promotion.
7
Production Environment
Live environment; artifact promoted only after all gates pass.
Distractors (wrong answers)
Deploy to Prod Before Testing Skip Artifact Registry Skip Staging
Module 9 Microservices System Design Live
1
API Gateway
Single external entry point; routes requests, handles auth and rate limiting.
2
Service Registry
Maintains live registry of service instances and their network locations.
3
Individual Microservices
Independently deployable services each owning a bounded context.
4
Message Broker (Event Bus)
Decouples services via async events; prevents direct service-to-service coupling.
5
Per-Service Database
Each service owns its own data store; no shared database across services.
6
Distributed Cache
Shared in-memory cache (Redis) reduces redundant DB queries across services.
7
Observability Stack
Centralized logs, distributed tracing, and metrics dashboards for the whole system.
Distractors (wrong answers)
Shared Monolithic Database Direct Service-to-Service Calls Without Registry Skip Message Broker
Module 10 Resilient Distributed System Design Live
1
Load Balancer
Distributes traffic across healthy instances; removes failed nodes from rotation.
2
Circuit Breaker
Detects downstream failure and stops sending requests, preventing cascade failures.
3
Retry with Exponential Backoff
Retries transient failures with increasing delays to avoid thundering-herd storms.
4
Bulkhead Isolation
Partitions thread pools and resources so one failing component cannot exhaust the whole system.
5
Replica Set (CAP-aware)
Data replicated across nodes; design acknowledges the CAP trade-off (CP or AP).
6
Distributed Tracing
Correlates requests across services to identify latency and failure hotspots.
7
Chaos Testing Framework
Deliberately injects failures in production-like environments to validate resiliency assumptions.
Distractors (wrong answers)
Single Point of Failure Node No Circuit Breaker Skip Replica Set
