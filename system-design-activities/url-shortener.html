URL Shortener Architecture

🔗 The Objective

Your URL shortener serves billions of redirects per day. Most short links are clicked repeatedly — hitting a database on every request would be far too slow and expensive.

Think about: How does a user's request first reach your system at scale? What logic must run to look up the original URL from the short code? Where should you check before touching persistent storage? When that fast layer doesn't have the answer, where is the source of truth?
