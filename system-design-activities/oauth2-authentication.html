OAuth 2.0 Authentication Flow

🔐 The Objective

A third-party app wants to access a user's Google data without ever seeing their Google password. Your design must let the user grant permission, issue secure credentials, and allow access to protected resources.

Think about: Where must the app send the user first to begin the login process? What critical step requires the user — not the app — to actively approve access? Why is a short-lived code exchanged for tokens in a separate back-channel step rather than returning tokens directly? What checks the token on every subsequent API call?
