Cache Performance

A cache is the highest-leverage tool in a system designer's toolkit. Redis responds in under 1 ms. A database query takes 10–100 ms. Multiply that by millions of requests per second and you see why cache hit rate is so critical. Slide the hit rate below and watch the database evaporate — or explode.

Cache-Aside (Lazy)

Check cache first. On miss, query DB, write result to cache, return. Most common pattern. Cache only stores what's actually requested.

read → cache miss → DB → cache.set() → return
✍️
Write-Through

Write to cache AND DB simultaneously. Cache is always fresh. Higher write latency, but zero stale reads. Good for write-heavy data.

write → cache.set() + DB.write() in parallel
📪
Write-Back (Async)

Write to cache only. DB is updated asynchronously later. Fastest writes, but risk of data loss if cache dies before flush.

write → cache.set() → queue → DB.write()
