RPS & Peak Load Estimation

🎯 Scenario

You are capacity-planning a new social media platform similar to Twitter. Before provisioning servers, you need to estimate how many requests per second (RPS) your system must handle — both on average and at peak traffic times. Your answers will determine how many application servers, database connections, and cache nodes to provision.

📋 Given Values

Daily Active Users (DAU): 300,000,000
Read actions per user/day: 20
Write actions per user/day: 2
Peak traffic multiplier: 3× (rush hours)
💡 Key formula: Average RPS = (Total daily actions) ÷ (Seconds per day)  |  Seconds per day = 24 × 60 × 60 = 86,400

🧮 Step-by-Step Calculations

Work through each step. Round to the nearest whole number where needed.

Step 1 — Total daily read actions
= DAU × reads per user = 300,000,000 × 20
actions/day
Step 2 — Total daily write actions
= DAU × writes per user = 300,000,000 × 2
actions/day
Step 3 — Average Read RPS
= Total daily reads ÷ 86,400
RPS
Step 4 — Average Write RPS
= Total daily writes ÷ 86,400
RPS
Step 5 — Peak Read RPS
= Average Read RPS × peak multiplier (3×)
RPS
Step 6 — Peak Write RPS
= Average Write RPS × peak multiplier (3×)
RPS
⭐ Step 7 — Total Peak RPS (system must handle)
= Peak Read RPS + Peak Write RPS
RPS
✅ Worked Solution
Step 1: 300,000,000 × 20 = 6,000,000,000 reads/day
Step 2: 300,000,000 × 2 = 600,000,000 writes/day
Step 3: 6,000,000,000 ÷ 86,400 = 69,444 Read RPS
Step 4: 600,000,000 ÷ 86,400 = 6,944 Write RPS
Step 5: 69,444 × 3 = 208,333 Peak Read RPS
Step 6: 6,944 × 3 = 20,833 Peak Write RPS
Step 7: 208,333 + 20,833 = 229,166 Total Peak RPS
📌 Engineer's takeaway: At ~229K peak RPS, assuming each app server handles ~2,000 RPS, you need at least 115 app servers at peak. Always provision with headroom — plan for 150–200 servers. The 3× peak multiplier is a common industry rule of thumb; Netflix uses up to 10× for live events.
