Cache Hit Rate & Database Load

📋 Scenario

A social media platform's read API handles 120,000 RPS at peak. The team introduces a Redis cache layer with an expected hit rate of 85%. Each database server can handle 5,000 read RPS before saturating. The team wants to know how many DB servers are needed with the cache in place, and what the cache miss rate is — and compare that to the no-cache scenario.

📊 Given Values

Peak Read RPS
120,000
Cache Hit Rate
85%
DB Capacity
5,000 RPS
Safety Buffer
20%
Key Formulas: Cache misses RPS = Total RPS × (1 − hit rate) | Cache miss % = 100 − hit% | DB servers needed = ⌈DB RPS / capacity per server⌉ | With buffer: divide by (1 − buffer%) before rounding up | No-cache DB servers = ⌈Total RPS / capacity⌉

🧮 Step-by-Step Calculation

Step 1 — Cache miss rate (%)
Formula: 100% − cache hit rate%
%
Step 2 — Cache hits served per second
Formula: 120,000 RPS × 0.85
RPS
Step 3 — Cache misses (reach the DB) per second
Formula: 120,000 × (1 − 0.85) or 120,000 − Step 2
RPS
Step 4 — Effective capacity per DB server with 20% buffer
Formula: 5,000 × (1 − 0.20) — run each server at 80% max
RPS/srv
Step 5 — DB servers needed WITH cache (round up)
Formula: ⌈cache misses RPS / effective capacity per server⌉
servers
Step 6 — DB servers needed WITHOUT any cache (round up)
Formula: ⌈120,000 / 4,000 effective RPS per server⌉
servers
Step 7 — DB servers saved by adding the cache
Formula: servers without cache − servers with cache
servers saved

✅ Worked Solution

Cache miss rate = 100 − 85 = 15%
Cache hits = 120,000 × 0.85 = 102,000 RPS (served by Redis)
Cache misses = 120,000 × 0.15 = 18,000 RPS (hit the DB)
Effective cap = 5,000 × 0.80 = 4,000 RPS/server
DB servers (w/) = ⌈18,000 / 4,000⌉ = 5 servers
DB servers (w/o) = ⌈120,000 / 4,000⌉ = 30 servers
Servers saved = 30 − 5 = 25 servers
Engineer's Takeaway: An 85% cache hit rate reduces DB load from 120K to 18K RPS — an 85% reduction. That translates from 30 DB servers down to just 5. A single Redis cluster often costs less than 1 DB server, making caching one of the highest ROI architectural decisions you can make. This is why Twitter used to cache ~95% of their timeline reads in Memcached.
