Latency Budget Decomposition

📋 Scenario

Your product team has set a P99 SLA of 300 ms end-to-end for the search API. A request travels through the following fixed infrastructure costs that you cannot reduce: DNS lookup (5 ms), TLS handshake (15 ms), CDN edge processing (8 ms), and network round-trip to origin (22 ms). The remaining budget must be split across three service layers: the API Gateway gets 10% of remaining budget, the Search Service gets 60%, and the Cache/DB layer gets the remaining 30%. Calculate each component's budget and flag whether each is realistic.

✅ Worked Solution

Fixed overhead = 5 + 15 + 8 + 22 = 50 ms
Remaining = 300 − 50 = 250 ms
API Gateway = 250 × 0.10 = 25 ms
Search Service = 250 × 0.60 = 150 ms
Cache / DB = 250 × 0.30 = 75 ms
Verify sum = 50 + 25 + 150 + 75 = 300 ms ✓
Fixed overhead% = (50 / 300) × 100 = 16.7% of SLA
Engineer's Takeaway: The fixed infrastructure overhead consumes ~17% of the total budget before a single line of application code runs. The Search Service has 150 ms — enough for one Elasticsearch query. The Cache/DB layer has 75 ms — Redis typically responds in <1 ms, so this budget is generous for a cache hit, but tight for a cache miss requiring a DB query + serialisation. This is why cache hit rate matters so much: a cache miss on a 50ms DB query uses 67% of the Cache/DB budget in one call.
