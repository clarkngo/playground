Key Concepts

GitHub Codespaces

  • Cloud-Based IDE: GitHub Codespaces is an online development environment that runs in the browser or via VS Code. It eliminates the need to install tools locally.
  • Built-in Terminal: Comes pre-configured with Git, Python, and other common tools.
  • Git Integration: Fully integrates with GitHub repositories for cloning, branching, committing, pushing, and creating pull requests directly inside Codespaces.
  • No Cloning Needed: When you open a Codespace, you are already inside the project repository.

Git Development Cycle (in Codespaces)

  • Branching: Use git checkout -b branch_name to create and switch to a new branch. Recommended for isolating features or fixes.
  • Status Check: Use git status to view untracked or modified files.
  • Staging Files: Use git add --all to stage all changes.
  • Committing Changes: Use git commit -m "message" to save changes in local history.
  • Pushing: Use git push origin branch_name to sync your local branch with GitHub.
  • Pull Request (PR): Created from the GitHub web interface to propose merging feature branches into main.
  • Pulling Changes: Use git pull to update your local repository with changes from the remote.

Debugging in Codespaces

  • Breakpoints: Add a red dot to pause execution at a specific line.
  • Start Debugging: Use Run → Start Debugging to begin.
  • F11 (Step Into): Enters inside a function call.
  • F10 (Step Over): Executes the current line and moves to the next one.
  • Interactive Console: View variable values and output during step-by-step execution.

Error Analysis

  • Syntax Errors: Typos, missing colons, incorrect indentation, or invalid syntax.
  • Problems Tab: Displays errors when files are saved with invalid Python syntax.

Linting

  • Pylint Setup: Install the Pylint extension from the VS Code Marketplace.
  • Automatic Detection: Saving a .py file shows style and logic warnings.
  • Problems Tab: Linting warnings appear alongside syntax errors.

Git Tools in Codespaces

  • Source Control Tab: View, commit, and push changes visually.
  • Settings: Ensure Git: Enabled is turned on.

Section 2: Git Development Cycle

0) Starting in Codespaces

When you open a Codespace, you’re already inside the repository — no need to clone. A terminal and editor (like VS Code) are already set up for you.

1) Creating a new branch using git checkout

This command creates a new branch and switches to it. Work on a separate branch so you do not affect main directly.

  1. Open the Terminal tab in Codespaces.
  2. Run:
git checkout -b hello-git-branch
  1. The output should match the handout. Take a screenshot as 01_new_branch_firstname_lastname.png.
Terminal output after running git checkout -b hello-git-branch.
Branch checkout confirmation showing the new branch name.

2) Listing current branches

A Git project can have more than one branch. List them with git branch.

  1. In your terminal, run:
git branch

If you do not see any branches, ensure you have a git repository in your working directory and at least one commit.

  1. Take 02_listing_branches_firstname_lastname.png.
