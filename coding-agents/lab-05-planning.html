📖 Concept Overview

Planning is what separates capable agents from reactive ones. A reactive agent simply picks the next action based on the current observation. A planning agent first builds a mental model of how to reach the goal — decomposing it into subtasks, identifying dependencies, and ordering execution to minimize wasted effort. This matters enormously for tasks with more than a few steps, where a naive approach leads to circular work or missed prerequisites.

The output of planning is typically a task DAG — a directed acyclic graph where nodes are subtasks and edges represent dependencies ("Task B cannot start until Task A is complete"). The DAG makes explicit which tasks can be parallelized (no dependencies between them) and which must be sequential. Finding the critical path through the DAG — the longest chain of dependent tasks — tells you the minimum possible time to complete the work, no matter how much parallelism you add.

Real coding agents use planning implicitly (the LLM reasons about order in its thoughts) or explicitly (outputting a structured plan that gets stored and executed step-by-step). Explicit planning is more robust for long-horizon tasks because the agent can check off completed steps, detect blockers, and replan when circumstances change — without relying on the model to remember what it's done from context alone.

⚙️ How Agents Plan
  1. Goal clarification
    Before planning, the agent clarifies what "done" looks like. Ambiguous goals produce unfocused plans. A good agent asks: "What are the success criteria? What constraints exist (time, budget, tools available)? Are there known blockers?" This context shapes the entire plan.
  2. Top-down decomposition
    Break the goal into 3–5 high-level subgoals. Then recursively break each subgoal into concrete, actionable tasks. Stop decomposing when tasks are small enough to complete in one agent loop iteration. Overly granular plans are hard to track; overly coarse plans miss dependencies.
  3. Dependency identification
    For each task pair, ask: "Can B start before A finishes?" If no, add a directed edge A → B. Common dependency patterns: setup must precede implementation; tests must follow implementation; documentation follows all code tasks. Capture these explicitly rather than assuming the executor will figure them out.
  4. Critical path analysis
    Run a longest-path algorithm on the DAG. The critical path is the sequence of dependent tasks that determines the total duration. Tasks not on the critical path have "slack" — they can be delayed or deprioritized without affecting the overall completion time. Focus optimization effort on critical path tasks.
  5. Execution with replanning
    Execute tasks in topological order, respecting dependencies. When a task completes, mark it done and unlock dependent tasks. When a task is blocked (tool failure, missing information), update the DAG and recompute the critical path. A good planner treats the plan as a living document, not a fixed script.
💡
Planning vs. ReAct: when to use which

ReAct (Lab 04) works well for tasks where the next step depends on what you just discovered. Planning works better when the task structure is known upfront and parallelism matters. In practice, the best agents combine both: a top-level planner generates the DAG, then each leaf task is executed with a mini ReAct loop that handles unexpected observations within that subtask.

⚠️
Over-planning wastes time

Generating a 50-step plan before taking any action is often a mistake — the world changes, early steps reveal new information, and half the plan becomes invalid. Prefer short plans with frequent replanning checkpoints. Plan 3–5 steps ahead, execute, observe, then replan based on what you learned.

📋 Plan Representation Formats
📝 Numbered list

Simplest format. Good for sequential tasks with no parallelism. The model outputs "1. Do X, 2. Do Y, 3. Do Z" and executes in order. Easy to parse, easy to track, but loses dependency structure.

🌳 Hierarchical outline

Nested lists showing subgoals and their leaf tasks. Captures hierarchy but not cross-branch dependencies. Good for documentation-style plans where humans review before execution.

🔗 JSON DAG

Explicit graph: each task has an id, description, depends_on list, and status. Parseable, executable, queryable. The format used by most production agent frameworks (LangGraph, CrewAI, etc.).

📋 Markdown TODO with checkboxes

Human-readable format that Claude Code uses. Tasks are - [ ] Task description; checked off as completed. Simple, auditable, and the model can easily read and update its own plan file.

🪤 Common Pitfalls
Circular dependencies

Task A depends on B which depends on A. This creates a deadlock the agent can never resolve. Fix: Validate the plan is a true DAG (no cycles) before execution. Most graph libraries include cycle detection.

Ignoring the critical path

Agents that execute tasks in arbitrary order (or alphabetical order) waste time on non-critical tasks while the bottleneck sits idle. Fix: Always schedule critical path tasks first; run non-critical parallel tasks only when resources permit.

Plan-execution gap

The plan says "do X" but the agent does Y because it "knows better" based on what it observed. This drift makes plans untrustworthy. Fix: If the agent deviates from the plan, it must explicitly update the plan — not silently diverge from it.

✅ Key Takeaways
→
Planning enables parallelism. Without a DAG, agents execute sequentially. A DAG makes explicit which tasks can run in parallel, often cutting total time by 50–80% for complex projects.
→
The critical path is your bottleneck. Optimizing non-critical tasks doesn't speed up the overall project. Identify the critical path first and focus effort there.
→
Plans must be living documents. A plan that can't be updated in response to new information is a liability. Build replanning into the agent loop, not as an afterthought.
→
Explicit plans are auditable. When an agent writes out its plan (in a TODO list, JSON, or document), humans can review, approve, or redirect before expensive execution begins.
