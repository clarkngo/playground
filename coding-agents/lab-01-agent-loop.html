The Agent Loop

Perceive → Think → Act → Observe — the heartbeat of every AI agent

PERCEIVE

      

    

  








  
📖 Concept Overview

  
The agent loop is the fundamental execution pattern that every AI agent follows, regardless of how sophisticated it appears. At its core, an agent is simply a program that runs this loop repeatedly: it senses its environment, reasons about what to do, takes an action, and then observes the consequences. This cycle repeats until the task is complete or a stopping condition is met.

  
What makes modern LLM-based agents different from older rule-based systems is the THINK phase. Instead of matching inputs to hand-coded rules, the agent uses a large language model to reason in natural language about what action to take. This reasoning can be made explicit through techniques like chain-of-thought prompting, where the model "thinks out loud" before deciding on an action.

  
The loop is also called the sense-plan-act cycle in classical AI, or the perception-action loop in robotics. The LLM agent version adds an explicit observation step after acting — feeding tool results back into context — which closes the feedback loop and allows the agent to adapt based on what actually happened.







  
⚙️ How It Works, Step by Step

  
    
    
  1. 
      
    
        
    PERCEIVE — Read the environment
    
        
    The agent receives input: a user message, a new file, a tool result, or a system event. This input is appended to the agent's context window — the running conversation log that the LLM can read. The context is the agent's only "memory" of what has happened so far.
    
      
    
    
    2. 
    
  2. 
      
    
        
    THINK — Reason about what to do
    
        
    The LLM generates a response to the current context. If chain-of-thought prompting is enabled, the model first produces a <thought> block (internal reasoning that isn't shown to the user) before deciding on its action. This is where the model plans, selects a tool, and prepares arguments.
    
      
    
    
    3. 
    
  3. 
      
    
        
    ACT — Execute a tool call or respond
    
        
    The model emits either a natural-language response (ending the loop) or a structured tool call — a JSON object specifying which function to run and with what arguments. The agent runtime intercepts this, routes it to the appropriate tool (search engine, code executor, file system, API), and runs it.
    
      
    
    
    4. 
    
  4. 
      
    
        
    OBSERVE — Inject the result into context
    
        
    The tool's output (stdout, JSON, error message, file contents) is appended to the context window as a new "tool result" message. The agent can now read what actually happened. If the result is incomplete or an error occurred, the next THINK phase can reason about how to recover.
    
      
    
    
    5. 
    
  5. 
      
    
        
    Repeat until done
    
        
    The loop runs until the model decides the task is complete (responds with a final answer rather than a tool call) or until a hard limit is hit — such as a maximum number of steps, a token budget, or a timeout. Well-designed agents include explicit stopping criteria to prevent infinite loops.
    
      
    
    
    6. 
  







  

    
💡

    

      
Why the loop matters for reliability

      
Each iteration of the loop is a checkpoint. If a tool fails, the agent observes the error and can retry with different arguments, choose a different tool, or ask the user for clarification. This makes agents more robust than a single-shot LLM call — they can self-correct in real time rather than hallucinating an answer.

    

  

  

    
⚠️

    

      
The loop has a cost: tokens accumulate

      
Every iteration appends more content to the context. Tool results, intermediate thoughts, and action history all consume tokens. A task requiring 20 tool calls might use 50,000+ tokens by the end. This is why context management (Lab 03) and planning (Lab 05) are so important — they reduce unnecessary loop iterations.

🪤 Common Pitfalls

  

    

      
Infinite loops / getting stuck

      
An agent may repeatedly call the same tool with the same arguments if it doesn't reason about past failures. Fix: Inject a "steps taken so far" summary into each THINK phase, or use a max-iterations guard.

    

    

      
Context overflow

      
After many iterations, the context window fills up. Older messages get truncated, and the agent "forgets" what it did early in the task. Fix: Summarize old turns, use RAG for long-term memory, or compress tool results.

    

    

      
Acting before thinking

      
Without chain-of-thought, models sometimes jump to an action that seems obvious but misses important context. Fix: Always prompt the model to reason in a <thought> block before emitting a tool call.

    

  







  
✅ Key Takeaways

  

    

      
→

      
Every agent is a loop. No matter how complex — Devin, Claude Code, AutoGPT — they all reduce to: perceive, think, act, observe, repeat.

    

    

      
→

      
The context window is the agent's working memory. Each loop iteration reads from and writes to this shared space. Managing it carefully is essential for long-horizon tasks.

    

    

      
→

      
The OBSERVE step is what makes agents adaptive. Feeding actual tool results back in (not just assumed results) is what allows self-correction and real-world grounding.

    

    

      
→

      
Loop cost grows with task complexity. Budget your token allowance per task and implement stopping conditions — agents that loop forever are expensive and unpredictable.
