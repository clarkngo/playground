Comparing direct answers, CoT reasoning, and the Thought/Action/Observation loop

📖 Concept Overview

Chain-of-Thought (CoT) prompting is a technique where you instruct the LLM to reason step-by-step before giving its final answer. Instead of immediately outputting "42", the model first writes out its reasoning: "The user wants X, so I need to Y, which means Z, therefore the answer is 42." This seemingly simple change dramatically improves accuracy on multi-step problems — the model is less likely to make reasoning errors because each step is explicitly verified before the next.

The ReAct pattern (Reasoning + Acting) extends CoT into an interactive loop. Rather than reasoning all the way to a final answer in one pass, the model alternates between Thought (internal reasoning about what to do next), Action (a tool call to gather information or perform an action), and Observation (the result of that action). This interleaving allows the model to update its reasoning based on real-world feedback — correcting course when a search returns unexpected results or a tool call fails.

ReAct is particularly powerful because it grounds reasoning in reality. A pure CoT model might reason its way to a wrong answer confidently; a ReAct agent observes actual evidence and adjusts. This is why ReAct-style agents are the dominant architecture for tasks requiring real-world information retrieval or multi-step execution.

⚖️ Comparing the Three Approaches
Approach How It Works Best For Token Cost Self-Correction
Direct Answer Input → immediate output, no intermediate reasoning Simple factual Q&A, classification, short completions Lowest None — errors are silent
Chain of Thought Input → step-by-step reasoning → answer (one pass) Math, logic puzzles, multi-step deductions with known facts Medium (2–5× direct) Partial — catches reasoning errors
ReAct Thought → Action → Observation → Thought → ... → Answer Research, code execution, any task needing real-world data Highest (varies by # of steps) Strong — grounded in real observations
⚙️ How to Implement ReAct
  1. Set the pattern in the system prompt
    Tell the model explicitly: "Before each action, write a Thought explaining your reasoning. After receiving a tool result, write an Observation summarizing what you learned. Alternate Thought/Action/Observation until you have enough information to give a final Answer." Explicit instruction is required — models don't do this by default.
  2. Parse and execute Action blocks
    Your agent runtime needs to detect when the model emits an Action: block, parse the tool name and arguments, execute the tool, and inject the result as an Observation: message before continuing generation. This can be done with stop sequences or by using the model's native tool-use API.
  3. Let Thoughts be private
    In most agent UIs, the Thought blocks are hidden from users — they're the model's scratchpad. Only the final Answer is shown. This is similar to how Claude's extended thinking works: the reasoning is used internally but not surfaced to the end user.
  4. Handle dead ends gracefully
    Sometimes the model's Thought leads to an Action that returns an error or irrelevant result. A good ReAct implementation catches this in the Observation phase: "The search returned no results. I should try a different query." This self-correction ability is ReAct's key advantage over pure CoT.
💡
Extended Thinking vs. Chain-of-Thought

Modern models like Claude 3.7 Sonnet support "extended thinking" — a first-class API feature where the model's reasoning is done in a separate hidden scratchpad before producing its response. This is similar to CoT but with a key difference: the reasoning tokens don't count against the visible context and can use a much larger budget. Extended thinking consistently outperforms standard CoT on complex reasoning tasks.

✅
When NOT to use ReAct

ReAct adds significant latency (multiple round-trips) and token cost. For tasks with stable, known answers (writing a poem, translating text, simple code completions), ReAct is overkill. Reserve it for tasks that genuinely require external information or multi-step execution. Use direct answers for everything else.

✅ Key Takeaways
→
Thinking before answering dramatically improves accuracy. CoT works because it forces the model to commit to each reasoning step before moving on, catching errors early rather than in the final answer.
→
ReAct grounds reasoning in reality. By interleaving actions and observations with thoughts, the model can't hallucinate its way to a confident wrong answer — it must confront real-world feedback.
→
There's a cost-accuracy tradeoff. Direct answers are fast and cheap. CoT is slower and more accurate. ReAct is slowest but most reliable for complex tasks. Match the approach to the task complexity.
→
Thoughts are the agent's scratchpad. They don't need to be perfect prose — they're working memory. What matters is that reasoning happens explicitly before action, not that it's beautiful.
