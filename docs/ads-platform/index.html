Platform Architecture Overview

eBay Ads Platform - Complete System Architecture & Components

Core Pillars

🎯 Advertising Programs

Multiple tiers of ad products tailored to seller needs - from cost-per-sale to real-time bidding auctions.

📊 Data & Analytics

Real-time processing of billions of events with Kafka, Flink, and ClickHouse for immediate insights.

🔧 Infrastructure

Kubernetes-based microservices architecture with containerized deployments and multi-region failover.

⚙️ Operations

Round-the-clock SRE team with automated monitoring, alerting, and incident management.

💰 Monetization

Multiple revenue models: CPM, CPC, CPA, and fixed-price campaigns with CRM integration.

🛡️ Quality Assurance

Continuous A/B testing, anomaly detection, and fraud prevention mechanisms.

Scale & Complexity

The platform handles:

  • Billions of events daily - clicks, impressions, conversions tracked in real-time
  • Petabytes of historical data - stored in Hadoop (Apollo/Hermes) for analytics
  • Multi-region deployment - distributed across global data centers
  • 99.99% uptime SLA - critical for revenue generation
  • Sub-millisecond latency - required for real-time bidding auctions

Core Advertising Concepts & Terminology

Advertising Programs

Program Model Description
PLS
(Promoted Listings Standard)		 Cost-Per-Sale (CPS) Fixed percentage of sale price. Sellers pay only when their item sells.
PLA
(Promoted Listings Advanced)		 Cost-Per-Click (CPC) Keyword-targeted bidding platform with real-time auction. Sellers bid on keywords.
PLX
(Promoted Listings Express)		 Simplified CPC Simplified ad tier with automatic bidding and less configuration.
SFA
(Seller-Funded Ads)		 Auction-Based eBay-owned inventory sold to sellers through DSP/SSP programmatic platform.
Promoted Display CPM / Fixed Banner and brand solutions with guaranteed/non-guaranteed inventory placements.

Monetization Models

CPM (Cost Per Mil)

Advertisers pay per 1,000 impressions. Used for display and brand awareness campaigns.

CPC (Cost Per Click)

Advertisers pay only when user clicks. Real-time bidding model used in PLA.

CPA/CPO (Cost Per Acquisition)

Payment triggered by user action or purchase. Common in affiliate and performance marketing.

Fixed Price / Tenancy

Flat-rate premium placements like homepage takeover. Event-based pricing.

Key Performance Indicators (KPIs)

  • GMV (Gross Merchandise Value) - Total sales amount driven through the platform
  • PL-Enabled GMV - GMV directly attributable to Promoted Listings
  • ROAS (Return on Ad Spend) - GMV ÷ Ad Revenue (used to measure campaign efficiency)
  • Attribution Ratio - Percentage of sales attributed to ad clicks
  • Take Rate / Sold Ad Rate - Effective fee rate charged for sold ads
  • Click-Through Rate (CTR) - Clicks ÷ Impressions
  • Conversion Rate - Sales ÷ Clicks

    • Ad Tech Ecosystem

    DSP (Demand-Side Platform)

    eBay-owned tool allowing programmatic ad buying. Advertisers/sellers use DSP to purchase inventory.

    SSP (Supply-Side Platform)

    eBay-owned tool for seller-side inventory management. Publishers use SSP to sell impressions.

    RTB (Real-Time Bidding)

    Instantaneous auction environment where impressions are bought/sold programmatically.

    Technology Stack

    📊 Data & Streaming Layer

    • Rheos & Kafka - Internal messaging and event streaming for real-time data flow (clicks, impressions, conversions)
    • Apache Flink - Real-time stream processing and aggregations
    • Apache Spark - Distributed data processing for batch and intermediate jobs
    • Hadoop (Apollo/Hermes) - Heavy offline batch processing, deduplication, and long-term storage

    💾 Databases & Query Engines

    • ClickHouse (NuColumnar) - Highly performant columnar database for real-time metrics, analytics, and reporting
    • Elasticsearch (Pronto) - Log storage, anomaly detection, monitoring, and aggregated metadata
    • Cassini - Core internal search engine for product discovery and targeting
    • MongoDB - Configuration and campaign metadata storage

    ☁️ Infrastructure & Orchestration

    • Kubernetes (Tess.io) - Container orchestration for microservices, workers, and web apps
    • Docker - Containerization for reproducible deployments
    • Cloud Console - Internal deployment management

    📈 Monitoring & Observability

    • Control Center (Shepherd) - Central observability hub for health monitoring, metrics, alerts, and change tracking
    • Sherlock.IO - Anomaly detection and log analysis
    • Prometheus & Grafana - Time-series metrics, monitoring, and PromQL-based alerting
    • PagerDuty - Incident alerting and on-call management
    • Slack - Real-time notifications and incident communication

    🎨 Frontend & Rendering

    • MFE (Merch Front End) - Rendering layer for microservice-based UIs
    • Nori - Middleware for asynchronous ad module loading and data structuring

    🏢 Business Systems

    • Hive CRM (Salesforce) - Sales contract management and Insertion Order (IO) creation
    • Contract Management System (CMS) - Legal and Controlling approval workflows
    • ServiceNow - Change tracking and deployment logging

    🧪 Experimentation & Testing

    • Touchstone - A/B testing framework and management platform
    • Legacy ET Tags - Placement-level experiment tracking
    • Modern XT Tags - Event-level experiment tracking for near-real-time impact analysis

    Advertising Programs Deep Dive

    🏆 Promoted Listings Standard (PLS)

    Pricing Model

    Cost Per Sale (CPS) - Seller pays percentage of sale price after item sells

    Target Users

    Beginner sellers seeking simple, risk-free ad model (pay only when items sell)

    Key Metric

    ROAS - Return on ad spend monitors efficiency

    Placement

    Search Results Page (SRP) and category pages with high visibility

    ⚡ Promoted Listings Advanced (PLA)

    Pricing Model

    Cost Per Click (CPC) via real-time bidding. Sellers bid on keywords.

    Target Users

    Advanced sellers with big budgets seeking precise keyword targeting

    Key Feature

    Real-time keyword auctions with bid recommendations from ML models

    Technology

    Uses DSP for programmatic bidding and attribution tracking

    ✨ Seller-Funded Ads (SFA)

    Programmatic Partnership

    eBay-owned inventory (off-platform partnerships, affiliate placements) sold to sellers through DSP/SSP infrastructure. Gives sellers access to external ad networks.

    🎨 Promoted Display & Brand Solutions

    Banner Ads

    Visual ads displayed across category pages and seller hubs

    Brand Solutions

    Premium, guaranteed placements for major brand campaigns

    Pricing

    CPM (cost-per-thousand impressions) or fixed price for tenancy

    Monetization

    Revenue from guaranteed and non-guaranteed inventory pools

    Core Workflows & Processes

    1️⃣ Tracking & Attribution (Sojourner System)

    Purpose: Track user behavior and accurately map the path from impression to conversion.

    Key Components

    • UBI Tables - User Behavior Interaction logs tracking clicks and page views
    • siid Tag - Source Impression ID identifying the original ad impression
    • ciid Tag - Current Impression ID for multi-tab tracking

    Challenge: Accounting for multi-tab browsing and missing data in attribution chains.

    2️⃣ Experimentation & A/B Testing (Touchstone)

    Purpose: Continuously test improvements without impacting production revenue.

    Experiment Design
    →
    Tag Setup
    →
    Real-Time Monitoring
    →
    Decision
    • Legacy ET Tags - Placement-level experiment tracking
    • Modern XT Tags - Event-level tracking for near-real-time impact analysis
    • Metric Dashboards - Real-time visibility into experiment impact on GMV, clicks, impressions

    3️⃣ Code Rollout & Deployment

    Purpose: Safely deploy code changes while tracking correlation with metric anomalies.

    PR + Jira
    →
    Jenkins Build
    →
    Staging Deploy
    →
    Prod Deploy
    • Docker Images - Built via Jenkins from merged code
    • Sequential Deployment - Workers → Beat → API → Other services
    • codeChangeScrubber - Logs deployments to ServiceNow and Control Center
    • Manifest Tracking - Links code commits to production versions for quick RCA

    4️⃣ Data Validation Workflow

    Purpose: Ensure data integrity across the entire pipeline.

    • Scheduled jobs cross-check metric accuracy (ClickHouse ↔ HDFS ↔ Elasticsearch)
    • Automated success/failure email notifications to ops teams
    • Reconciliation dashboards alert on data discrepancies

    5️⃣ Front-End Optimization (Vision Zero)

    Purpose: Prevent site degradation when backend services fail.

    • Ad SLAs - Strict load time requirements for ad modules
    • Napkin Async Loading - Lazy-load ads to prevent page collapse
    • Fallback Rendering - Graceful degradation when Cassini or pricing services timeout

    6️⃣ Contract & Sales Workflow (Hive CRM)

    Purpose: Manage advertiser contracts and track revenue.

    Create IO
    →
    Approval
    →
    Deploy to Ad Server
    →
    Sync Billing Data
    • Standard Contracts - Use pre-approved templates, fast approval
    • Non-Standard Contracts - Require Legal and Controlling review in CMS
    • Ad Server Sync - DFP/Google Ad Manager syncs impression data back to Hive

    Operations & Incident Management

    🚨 Incident Response Workflow

    SLA: L1 Infra and L2 Domain/QE must respond within 15 minutes of alert.

    Phase 1: Alert & Triage (0-5 min)

    • PagerDuty fires alert on threshold breach (GMV drop, click drop, latency spike)
    • Slack notification with metric dashboard link
    • On-call engineer acknowledges and begins investigation

    Phase 2: Investigation (5-15 min)

    • Check Sherlock for log anomalies and error patterns
    • Review Control Center for recent deployments, experiments, or config changes
    • Query Prometheus/Grafana for service-level metrics (latency, error rate, CPU)
    • Check CAL logs for batch job failures or data pipeline issues

    Phase 3: Remediation (15+ min)

    • Rollback problematic code, experiment, or config change
    • Scale services up/down if resource-constrained
    • Restart failed workers or batch jobs
    • Monitor metrics to confirm recovery

    📝 Post-Incident Review (RCA)

    • Document Timeline - When alert fired, when diagnosed, when fixed
    • Root Cause Analysis - What code/config/experiment caused it?
    • Revenue Impact - Estimated lost GMV and ad impressions
    • Preventative Measures - Tests, alerts, or architectural changes to prevent recurrence

    ⚠️ Common Incident Types

    Incident Type Typical Cause Investigation Tools
    GMV Drop Config error, bug in ranking, experiment ramping up Control Center, Sherlock, Experiment Dashboard
    Click/Impression Drop Cassini latency, ad rendering issue, Frontend bug Prometheus latency graphs, Frontend logs
    Data Delay Kafka broker down, Flink job stuck, ClickHouse ingestion lag Kafka/Flink dashboards, ClickHouse query logs
    Attribution Mismatch Tracking tag missing, UBI pipeline failure, Sojourner bug CAL logs, UBI table schema changes, Sojourner logs
    Billing Discrepancy Hive CRM sync failure, ClickHouse reconciliation lag Hive logs, reconciliation dashboards
